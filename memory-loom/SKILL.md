# Memory Loom · 项目织忆

把当前项目的事实、决定和交接信息保存在项目内，按需要检索。共享的是这份方法；各项目的内容不存入 skill、用户级记忆或其他项目。默认用中文记录，服从项目已有语言约定。

## 首次启用

1. 确认用户当前操作的**实际项目根目录**，阅读该范围的 `AGENTS.md` / `AGENTS.override.md` 及其引用规则。用户明确路径优先；否则结合当前项目、仓库与目标文件判断。不要把多项目容器目录当成所有子项目的共享记忆库；目标确实不明确时再问。
2. 仅检查本项目是否已有 `.project-memory/config.json` 或其他已明确配置的记忆入口。已有入口先遵守并复用，不为改名称而迁移。不要从父项目、兄弟项目或全局记忆中补充本项目背景。
3. 检查本项目是否已有 `工作记录/` 等任务档案。能兼容时以它作为 `--tasks-dir`，让每个任务只有一份正文；已有文件原样保留，用索引链接接入。若上层工作区另外强制要求工作记录，遵守该规则，本项目只保存指向该记录的最小定位信息；跨项目读取仍须用户明确指定，不复制其他项目内容。
4. 运行本 skill 目录下的脚本（`SKILL_DIR` 是当前读取到的 skill 绝对目录，不是假定的安装路径）：

   ```sh
   python3 "$SKILL_DIR/scripts/memory.py" init --root "$PROJECT_ROOT"
   # 若本项目已经用 工作记录/ 保存任务：加 --tasks-dir 工作记录
   ```

   新项目有明确时区约定时传 `--timezone`；否则脚本默认 `Asia/Shanghai`。已初始化项目优先沿用 `config.json`，不要重复传默认时区覆盖既有约定。初始化只在指定项目创建配置、工作流、导航、方向总结和任务目录，并为生效的项目指令文件补充可重复运行的入口。已有内容不重置。Python 不可用时按 [初始化与维护](references/maintenance.md) 手动建立同样结构。
5. 读取生成的 `.project-memory/MEMORY.md`，填充 `DIRECTION.md` 中本轮已明确的项目目标、范围和待确认问题。不要猜测项目路线。将首次启用作为一个任务记录，或者更新当前已有任务；在 `INDEX.md` 登记。执行 `check` 并报告真实结果。

## 后续使用

以项目内 [工作流模板](assets/MEMORY.md) 对应的 `.project-memory/MEMORY.md` 为执行依据。每次上下文首次进入项目读取这个小入口；它已经在上下文中时不重复读取。**无需先读所有记忆才能判断是否需要记忆。**

- 独立且信息充分的请求可直接执行，不读历史正文；涉及“继续、上次、之前为什么”、已有模块、历史约定或不确定目标时，先定向查导航。
- 同一目标的修复、追问和补充验证更新原任务。新聊天不等于新任务。需要独立验收的交付成果建新任务，并关联前序。
- 重要进展及时留检查点；正常收尾更新任务、导航和必要的方向总结。中断后以已保存检查点及实际文件为准，不能声称自动捕捉了未写入的对话。
- `INDEX.md` 是检索入口和关系图，不是完整档案；`DIRECTION.md` 是有来源的当前方向与复盘，不是无授权的待执行指令。

脚本入口：

```sh
python3 "$SKILL_DIR/scripts/memory.py" new-task --root "$PROJECT_ROOT" --title "任务名称" --summary "目标与范围" --keywords 模块名 关键词
python3 "$SKILL_DIR/scripts/memory.py" search --root "$PROJECT_ROOT" --query "关键词" --limit 5
python3 "$SKILL_DIR/scripts/memory.py" reindex --root "$PROJECT_ROOT"
python3 "$SKILL_DIR/scripts/memory.py" check --root "$PROJECT_ROOT"
```

`new-task` 只用于已经判定为新任务的请求；脚本不会理解语义或自动总结。`search` 只读检索任务元信息并限制输出数；需要正文匹配时才加 `--include-body`，它不检索导航中所有手工关系，也不取代必要的 `rg`。续写由 Codex 编辑原任务正文及元信息，再 `reindex`。详细记录格式、分流案例和检索策略见 [记录与检索](references/records.md)；结构损坏、旧记录接入、并行工作、归档及迁移才读 [初始化与维护](references/maintenance.md)。

## 实际能力边界

这是由项目指令驱动的文件记忆，不改变模型参数或上下文上限。首次为每个项目调用一次；后续依靠该项目指令入口执行。它不会监控 Codex“新建项目”事件、不会后台运行、不会保证异常退出前最后一步落盘。新聊天必须位于正确项目并加载其指令；项目下更具体的指令、覆盖文件或加载长度限制可能影响入口。不要声称已经验证跨会话自动加载，除非实际在新会话验证过。

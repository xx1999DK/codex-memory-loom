# 初始化与维护

仅在初始化、接入旧记录、结构异常、并行写入或整理时阅读。

## 生成结构

```text
项目根目录/
  AGENTS.md                    简短入口；若同级 override 生效则写入 override
  .project-memory/
    config.json                版本、项目 ID、时区、任务目录
    MEMORY.md                  项目日常工作流
    INDEX.md                   任务导航和知识关系
    DIRECTION.md               方向、决定、复盘、未解问题
    tasks/                     默认任务目录，可改用项目已有 工作记录/
```

`topics/` 和 `attachments/` 仅有内容时创建。任务默认使用日期、可读标题和短随机标识命名，防同标题碰撞；若项目有严格文件名规则，按规则安全重命名并同步导航，但保留 task_id。

## 无脚本初始化

Python 3.9+ 可用时优先脚本；不需要网络、API Key、数据库或第三方 Python 包。不可用时：

1. 在明确的项目根建立 `.project-memory/`，从 `assets/` 复制三个 Markdown 模板，不覆盖已存在的文件。
2. 创建 `config.json`：`version` 为数字 `1`，`project_id` 为新 UUID，`created` 为带时区的 ISO 8601 时间，`timezone` 为用户项目时区（默认 `Asia/Shanghai`），`tasks_dir` 为相对于项目根的目录字符串（默认 `.project-memory/tasks`）。不可含 `..` 或指向项目外。
3. 在生效的根 `AGENTS.override.md` 或 `AGENTS.md` 追加一次 `<!-- project-memory:start -->` 与 `<!-- project-memory:end -->` 包裹的短入口：开始时加载 `.project-memory/MEMORY.md` 的流程，历史按需读取；同任务续写、新任务建档；收尾同步任务、导航及必要的方向总结；只在本项目操作。
4. 保留原有规则。创建任务时按 [记录格式](records.md) 写完整元信息，导航任务表放在 `<!-- project-memory:tasks:start -->` 和 `<!-- project-memory:tasks:end -->` 之间，保留表外的人工关系。

无脚本时人工核查链接和状态；不要谎称通过了脚本检查。以后有 Python 时先 `check`，按实际差异补齐。

## 已有规则与记录

- 本项目 `agent.md` 若是现有规则的唯一来源，继续保留，入口可同时指向它和记忆流程，不复制整套规则。
- 初始化用 `--tasks-dir 工作记录` 可复用现存档案目录。无结构化 frontmatter 的旧记录不会被自动改写，在 `INDEX.md` “已有记录入口”中人工登记；后续续写仍编辑旧文件。
- 旧记录足够规范时可为其增补元信息并纳入生成表，保留文件名、正文、原创建日期和来源；删除手工导航中重复的定位条目。没有完整时间不要假装精确，应保留正文原时间说明并注明元信息补录时间来源。
- 上层多项目工作区的统一记录不属于本项目本地任务目录；不得用 `--tasks-dir ../工作记录` 越界。依照上层显式规则维护该记录，在本项目只存最小指向而非复制另一份事实；是否读取外部记录由用户授权和项目规则决定，脚本始终只处理本项目。
- 本机安装的 skill 更新不会自动覆盖既有项目的 `MEMORY.md`。需要升级时对比模板与本地修改、定向合并，保留项目约定，绝不能重新初始化来清空内容。

## 异常处理

- `init` 可重复运行；它保留原内容，不是修复或重置命令。配置损坏、未知版本、标记不完整、路径不安全时先检查具体错误。不要删目录重来。
- `reindex` 只重建 INDEX 内标记的任务表，不能恢复丢失的任务正文，也不会更新手工知识关系或方向总结。运行前先修正档案元信息。
- `check` 是只读结构检查；能发现的范围以其输出为准。它无法证明语义分流正确、结论真实、所有链接有效或每次聊天都执行过收尾。交付前仍核实本次变化涉及的正文和链接。
- 入口没有加载时检查实际项目根、同级 `AGENTS.override.md`、更具体的子目录指令及指令长度限制；在新聊天从正确项目启动验证。不要通过增加全局强制规则污染所有项目。
- `.project-memory.lock` 是脚本临时锁。锁冲突时先确认是否另有任务正在写入，等待或协调后重试；疑似崩溃残留先检查锁与运行状态，确认无人持有再处理，不自动抢锁或删除。
- 多代理时指定一个写入者维护 `INDEX.md` 和 `DIRECTION.md`。普通 Markdown 编辑不受脚本锁保护；修改前重新读取并合并差异。不要同时以旧快照整文件覆盖。

## 整理与迁移

先确保“当前交接摘要”准确，再整理旧材料；保存有用的历史决定、验证证据及来源。主任务档案保留原位置，把冗长日志分离到附件即可，不需要因为任务已完成就移动文件。若用户要求物理归档，先核对脚本索引支持的范围，更新全部链接并检查可检索性；不要丢掉旧任务的定位。

同一项目移动目录时因链接和配置使用相对路径，可保留身份。独立新项目从模板创建时，默认仅复制 skill 方法及空白模板，不复制旧 `.project-memory/` 或任务库。如果用户明确要求继承某些知识，注明来自哪个项目、何时导入，并分配新项目身份；手动迁移前备份相关文件，更新项目 ID 和对应元信息。Git worktree 不自动跨目录共享记忆，不把 Git 公共目录用作记忆根。

这些文件不自带备份或加密；沿用项目自己的备份和版本控制规则。不要自动改 `.gitignore`、提交、推送或部署。

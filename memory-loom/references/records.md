# 任务记录与按需检索

在建档、续写、导航不命中或需要调整记录粒度时读本文件。项目日常流程以其 `.project-memory/MEMORY.md` 为准。

## 新任务还是续写

| 请求 | 判定 | 动作 |
| --- | --- | --- |
| 昨天的导出功能还会乱码，继续修复 | 同一交付目标的缺陷 | 更新导出任务原记录，包括新验证 |
| 原来的导出功能现在补充测试 | 同一目标的验证 | 更新原记录，状态按实际结果调整 |
| 新聊天：继续上次的项目 | 信息不充分 | 搜索导航当前关注及未完任务，不猜测唯一当前任务 |
| 在导出功能之外开发用户权限 | 独立成果 | 新建权限任务并链接依赖 |
| 为什么当时选 SQLite | 项目历史问答 | 查决策来源；如有新解释或结论，更新所属任务 |
| 解释一个与项目无关的概念 | 独立问答 | 无需历史检索；有实质任务成果时建轻记录，避免无意义扩写 |
| 同一个修复后来发现根因判断错了 | 修正原任务 | 替换当前摘要中的错误结论，历史保留纠正依据 |

一次请求可延续多个明确任务，但不要为了每条消息建一份记录。先查候选记录的目标、交付物和验收范围；相似关键词只用于定位，不能决定合并。

## 结构化元信息

`new-task` 生成的 frontmatter 使用 YAML 的 JSON 值子集，字符串带双引号、列表使用 JSON 数组，便于仅用 Python 标准库解析。编辑时保持这个格式：

```yaml
---
task_id: "唯一 ID，保留脚本生成值"
project_id: "本项目 config.json 中的 ID"
title: "修复 CSV 中文导出"
created: "2026-10-27T10:00:00+08:00"
updated: "2026-10-27T11:30:00+08:00"
status: "待继续"
summary: "已修复编码；Windows Excel 实测待完成。"
keywords: ["CSV", "中文乱码", "export.ts"]
related: []
---
```

示例时间和 ID 不是可复制的真实元信息；新任务用脚本生成。`related` 保存同项目 task_id；正文补充实际可点击链接和关系。命名、旧记录格式另有项目规则时保留原约定，不为了满足结构化索引重复建档。

元信息是检索用摘要，正文才是完整证据；两者必须同步。`summary` 用一两句话写现状与剩余事项，避免将长文复制进索引。`updated` 是最后修改时间，不能替代结论的“最后验证时间”。不要变更已有任务的 `task_id`、`created` 或仅因跨日改名。

## 正文写什么

优先保证下一个执行者能接续：

- **目标与范围**：用户真正要达到的结果、验收条件、边界。
- **当前交接摘要**：当前状态、实际已完成、未完成、验证结果、关键路径、下一步。
- **执行与决策**：修改什么、为什么、涉及文件及配置；约束、失败尝试及排除依据。
- **验证与结果**：执行过的命令或操作、时间、结果；没运行的检查明确写未验证，避免复制无关大日志。
- **未解问题 / 后续**：待办、阻碍、解除条件；无待办明确写无。
- **更新记录**：按项目时区带日期追加，旧结论失效时写原因与替代来源。

文件路径相对项目或当前文档，Markdown 链接按所在文档目录解析；含空格时可用 `<...>` 包住目标，脚本索引使用 URL 编码。行号只是辅助定位，优先使用文件、符号或章节名，避免将旧行号当作可靠证据。

## 如何形成知识图谱

导航不需要是一张复杂图片；可检索的有向链接就够用，例如：

| 主题 | 关系 | 目标 | 证据 |
| --- | --- | --- | --- |
| CSV 导出 | 由此实现 | 导出任务链接 | 任务中的验证段 |
| CSV 乱码修复 | 修正 | 编码决定链接 | 新旧文件差异 |
| 用户权限 | 依赖 | 身份模型任务链接 | 当前设计文档 |

不要把示例写进真实项目。只登记当前项目已有事实；任务元信息中的关键词应含用户常用说法、关键模块和文件名。目录很大时按主题拆出 `.project-memory/topics/`，在 `INDEX.md` 留一行摘要和链接，避免首页长篇复述。

## 检索停止条件

脚本 `search --root <项目绝对路径> --query "多个 关键词" --limit 5` 返回有限数量的任务定位信息；默认匹配标题、关键词、摘要和 ID，`--include-body` 才匹配正文。它不会改档案或导航，不返回整篇正文。手工主题关系、未索引附件等仍通过导航和定向 `rg` 查找；不能把脚本零命中视为项目没有相关历史。

找到与当前目标对应的记录，并足以确定现状、关键约束、下一步和所需证据后停止。先读交接摘要，确有必要才读历史。

如果已知任务 ID，直接搜索 ID；如果只知模块，先在索引搜索模块和别名；没有命中再对配置中的任务目录定向 `rg`，必要时检查文件列表以发现漏索引。不要一次 `cat` 所有 Markdown，也不要把未命中解释为“项目从未做过此事”。

对过时且会影响当前决策的内容重新核实。无法核实则保留不确定性，不盲目删除，也不当成既定约束。
